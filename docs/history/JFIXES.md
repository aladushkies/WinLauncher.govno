# WinLauncher Root — раунд J: построчный дебаг и чистка репозитория

**База:** раунд I (`docs/history/IFIXES.md`), 23 Java-файла, ~5 900 строк.
**Метод:** сплошное построчное чтение всех исходников + **реальная компиляция** против
`android.jar` (API 35) настоящим `javac` — проект до сих пор не имел ни одного шага сборки,
который действительно доказывал бы, что код компилируется.
**Итог статических проверок:** `tools/verify_quality.py` — **169/169 PASS** (было 159/159, но
они не выполнялись: скрипт падал на отсутствующем `.gitignore` после 37-й проверки).
**Компиляция:** 71 class file, 0 ошибок, 0 предупреждений кроме устаревших API Android.

## 1. Найденные и исправленные дефекты

### J-01 (критично) — `resizeTask` вызывался с неверным типом аргумента

`RootServer.handle()` вызывал `invoke(activityManager, "resizeTask", taskId, bounds, j.optInt("m", 0))`.
AOSP 6.0+ (в т.ч. 7.1.1 на SM-T555) объявляет `IActivityManager.resizeTask(int taskId, Rect r, boolean resize)`.
`RootServer.invoke()` сопоставляет типы строго (`compatible()`): `int` **не** подходит к `boolean`,
поэтому ни один overload не совпадал → `NoSuchMethodException` → **любое изменение размера окна
падало с ошибкой**. При этом `moveTaskToStack` передавал `Boolean` и работал — дефект был
неочевиден.

Флаг `"m"` — внутренняя подсказка лаунчера (commit vs. живой drag), а не AOSP-флаг «только
переместить». Окно должно реально менять размер, поэтому передаётся `true`.

*Исправлено:* новый метод `RootServer.resizeTask(int, Rect)` — вызов boolean-overload с
fallback на двухаргументную форму `resizeTask(int, Rect)` для старых прошивок.

### J-02 (критично) — компонент задачи терялся, если в прошивке нет `StackInfo.taskNames`

`RootServer.snapshotTasks()` брал `component` из поля `taskNames`. На API 25 этого поля в
`ActivityManager.StackInfo` нет, `stringArrayField()` возвращал пустой массив, и **все** задачи
отдавали пустой `component`. Последствия: у всех окон заголовок «Окно», нет иконок, а фильтр
«свои пакеты» (`pkg.equals(ownPackage)`) переставал работать — в модель попадали собственные
активности лаунчера.

*Исправлено:* fallback на `StackInfo.tasks[].baseIntent` (`Intent.getComponent()` /
`Intent.getPackage()`), который есть во всех поддерживаемых ветках. `taskNames` используется как
основной источник, когда он присутствует.

### J-03 (средне) — radio-переключатели сообщали запрошенное, а не фактическое состояние

`performDeviceAction()` перечитывал состояние только для авиарежима; Wi-Fi/Bluetooth/мобильные
данные возвращали `enabled` из запроса. Action Center показывал «Вкл.» даже там, где прошивка
молча отвергла команду `svc` (vendor-ограничения, политика SIM). Расходилось с собственным
комментарием D-11 в коде.

*Исправлено:* после любой команды состояние перечитывается через `readDeviceState(action)`;
если перечитывание не удалось — возвращается `known=false`, и UI честно сообщает, что
состояние не подтверждено.

### J-04 (высоко) — freeform-stack был зашит как литерал `2` в четырёх местах

`WindowController` принимает freeform stack id через конструктор (по умолчанию 2), но
`ChromeManager`, `TaskbarOverlay`, `SnapController` и `TaskViewOverlay` фильтровали окна по
`w.stackId == 2`. При любом другом freeform-стеке заголовки окон не создавались, панель задач
не показывала кнопок, Snap Assist не имел кандидатов, Task View скрывал окна.

*Исправлено:* добавлен `WindowController.freeformStackId()`; все четыре места используют его.

### J-05 (средне) — Edge Lite уничтожал WebView, не отцепив его от родителя

`EdgeLiteActivity.onDestroy()` вызывал `tab.web.destroy()` на вкладке, которая ещё была
child'ом `pageSlot`. Платформа требует сначала убрать view из иерархии.

*Исправлено:* `removeView()` из родителя выполняется до `destroy()`.

### J-06 (средне) — у сохранённой записи задачи было два несовместимых писателя

`LauncherPrefs.setWindowBounds()` писал запись `task_<id>` в формате `l,t,r,b,state` (через
запятую), тогда как `saveMinimizedState()` / `restorePersistedMinimizedState()` используют
pipe-формат из семи полей. Метод не вызывался, но любой будущий вызов испортил бы сохранённое
состояние свёрнутого окна.

*Исправлено:* несовместимый писатель удалён; формат записи теперь один.

### J-07 (средне) — один отклонённый resize-grip отменял обновление остальных

`ResizeGripManager.update()` при неудаче `wm.addView()` делал `return` — направления, которые
ещё не были созданы, оставались невидимыми хит-зонами 1×1 в точке (0,0).

*Исправлено:* `continue` вместо `return`.

### J-08 (низко) — `LauncherPrefs` создавался на каждое событие Accessibility

`KeyService.onAccessibilityEvent()` создавал новый `LauncherPrefs` (и обращение к
`SharedPreferences`) на каждый callback — заметная нагрузка для слабого устройства.

*Исправлено:* поле, создаваемое один раз на экземпляр сервиса.

## 2. Проверено и признано корректным (изменений нет)

* `clamp()` в `WindowController` может вывести окно за правый/нижний край рабочей области —
  это поведение в духе Windows (окно частично уходит за экран), менять нельзя.
* `DesktopActivity` не вызывает `widgetHost.destroy()`: такого публичного метода у
  `AppWidgetHost` нет, есть только `stopListening()` (уже вызывается) и `deleteHost()`,
  который **удалил бы виджеты пользователя**. Проверено по `android.jar` — исправление не
  требуется.
* `Intent.getPackageName()` не существует; использован `Intent.getPackage()` — проверено
  компиляцией.
* Аутентификация root-моста (токен через stdin, `H(token:nonce)` с раздельными доменами,
  проверка `peerUid`, abstract namespace) — корректна.
* `RootBridge` (схлопывание resize-запросов, таймауты, повтор идемпотентных команд, разрыв
  сокета при любой ошибке) — корректен.
* `SnapController.snap()`, своп ячеек, разделители, `DockedPairManager` (в т.ч. откат
  неудавшегося первого переноса пары) — корректны.

## 3. Новые проверки

`tools/verify_quality.py` дополнен пунктами **J-01…J-10** (169 проверок всего).

`tools/compile_check.py` — отдельный gate: компилирует все 23 файла против `android.jar`
(API 35) настоящим `javac` и печатает число class-файлов. Запускается и отдельно:

```sh
ANDROID_JAR=/path/to/android-35.jar JAVA_HOME=/path/to/jdk python3 tools/compile_check.py
```

Без JDK или без `android.jar` gate печатает `SKIP` (не `FAIL`) и не блокирует статические
проверки. В верификаторе это пункт J-09.
