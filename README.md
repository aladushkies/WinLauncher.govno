# WinLauncher Root — P1 + P2 (ядро root и базовое управление окнами)

Проект содержит P1 (RootServer + RootBridge) и первый P2-инкремент: `WindowController`, модель `Win` и `ChromeManager` с непрозрачными системными заголовками, кнопками свернуть/развернуть/закрыть и drag за строку заголовка. Целевая платформа — Galaxy Tab A 9.7 / Android 7.1.1 (API 25). В APK включены постоянный root-процесс `app_process`, абстрактный LocalSocket, токен + проверка UID, JSON-команды `ping`, `tasks`, `resize`, `front`, `stack`, `close` и клиент с последовательной очередью и coalescing для `resize:<taskId>`. Заголовки показываются только для видимых задач в стеке 2; мониторинг списка задач пока опрашивает RootServer каждые 750 мс.

## Сборка APK

Требуется Android Studio с Android SDK Platform 35 и JDK 17 (AGP 8.6.1). Откройте каталог `WinLauncherRoot` как Gradle-проект или выполните:

```sh
gradle :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. `minSdk=25`, `targetSdk=25`; приложение остаётся техническим прототипом и пока не является готовым лаунчером. Сборка в текущей рабочей среде не была проверена: Android SDK и Gradle там не установлены.

## Проверка на устройстве

1. Установить APK и открыть его.
2. Нажать «1 · Запустить RootServer», одобрить запрос SuperSU/Magisk.
3. Нажать «2 · Проверить root-соединение» — ответ должен содержать `ok:true`, `uid:0`, `api:25`.
4. Выдать WinLauncher разрешение отображения поверх окон. Экран разрешения открывается кнопкой заголовков; если нужно, выдать root-командой `appops set ru.winlauncher SYSTEM_ALERT_WINDOW allow`.
5. Включить на устройстве freeform и открыть пару тестовых приложений в свободных окнах.
6. Нажать «3 · Сканировать задачи» для проверки JSON и «4 · Включить заголовки окон» для пробного chrome.
7. Проверить клики, drag, maximize/fullscreen, minimize/restore и close только на тестовых задачах. «5 · Скрыть заголовки» убирает все оверлеи.

Ответ `tasks` содержит `id`, `stack`, `component`, `bounds`, `visible`, `z`. Эксперименты с перемещением задачи между стеками и minimize-парковкой всё ещё нужно подтвердить на реальном SM-T555.

## Границы этого инкремента

- Вызовы скрытого `IActivityManager` делаются reflection-ом. Это избавляет от нестабильных API-stubs при компиляции, но не отменяет проверку имен/сигнатур именно на Samsung API 25.
- Имена стеков `1/2/3`, формат bounds, порядок задач, способность Samsung перемещать/изменять размеры, запуск `app_process` через конкретный SU-менеджер и peer credentials должны быть проверены на устройстве. Реальных результатов устройства в проект не подставлено.
- Пока нет `ITaskStackListener`, автоподписки на события, `start`, `thumb`, `shot`, `key`, настройки status bar и произвольной команды root shell. `tasks` запрашивается явно. Это намеренно ограниченный первый модуль.
- Сервер использует `LocalServerSocket` в abstract namespace. Любая ошибка извлечения UID peer-а приводит к отказу сессии (fail closed).
- Если RootServer уже запущен, повторная команда запуска может завершиться ошибкой bind; это не мешает подключению к существующему серверу.
- P2 пока без `ITaskStackListener`: используется polling 750 мс. Окклюзия заголовков, snap, restore-курсор, системное меню и taskbar ещё не сделаны. В fullscreen есть только экспериментальная верхняя touch-зона 3 dp: свайп вниз возвращает задачу в MAX; нижняя зона панели задач пока отсутствует.
- `TYPE_SYSTEM_ALERT` и перекрытие Samsung-caption проверяются только на целевом устройстве. Реализация не находит автоматически высоту caption Samsung и использует 32 dp.
- Переходы в fullscreen и minimize используют экспериментальные stack IDs из ТЗ (`1` и `2`). Не проверяйте на важных задачах, пока не подтверждены E-1/E-2.

## Протокол

Первая строка: `{"token":"<64 hex>","uid":<app uid>}`. Далее строки JSON с `id` и `c`. Каждый ответ содержит `id` и `ok`; `tasks` возвращает `tasks`. Ошибки Binder/hidden API возвращаются как `ok:false` и короткий текст.
